# TinyTuya → Zabbix: мониторинг умных розеток

[English documentation](README.md) · [Настройки](docs/CONFIGURATION.ru.md) · [Лицензия](LICENSE)

Локальный мониторинг Wi-Fi-розеток Tuya через **TinyTuya** и **Zabbix 8.2** в Docker. Не нужны **Home Assistant**, установленный в TOS Python, SNMP и обращения к Tuya Cloud при регулярном опросе.

> Это независимый проект. Совместимость локального протокола и набор DPS зависят от модели и версии прошивки устройства.

## Возможности

- Опрос розетки по LAN (по умолчанию раз в 60 секунд), протокол Tuya 3.5.
- Состояние реле, напряжение, ток, мощность, при наличии — таймер и режим восстановления питания.
- Передача двух элементов типа Zabbix trapper: `tuya.poll.ok` и `tuya.status.raw`. Остальные метрики извлекаются через зависимые элементы; включены три графика и триггеры.
- **Только чтение**: скрипт использует `status()` и никогда не переключает реле.
- Ошибка отправки в Zabbix больше не считается ошибкой розетки.
- Local Key берётся из существующего файла TinyTuya `devices.json`, смонтированного только для чтения. Ключ не вшивается в образ.
- Один контейнер — одна розетка. Для нескольких устройств можно запустить несколько экземпляров образа.

**Важно:** мгновенная мощность в ваттах — не то же самое, что накопленная энергия в кВт·ч. Если устройство не передаёт счётчик, шаблон не создаёт фиктивные данные.

## Требования

- Docker Engine и Docker Compose v2 (например, TerraMaster TOS).
- IP, Device ID, протокол и Local Key розетки Tuya; устройство доступно по локальной сети.
- `devices.json`, полученный через TinyTuya Wizard. Этот файл не размещать в Git.
- Zabbix Server, доступный по TCP 10051, и созданный узел сети с корректным техническим именем.

## Быстрый запуск с локальной сборкой

1. Скачай исходники и распакуй в `/Volume1/docker/tinytuya-zabbix`.
2. Импортируй `zabbix/Tuya_Smart_Plug_by_TinyTuya_Zabbix_8.2.xml` через **Сбор данных → Шаблоны → Импорт**.
3. Создай хост и привяжи шаблон **Tuya Smart Plug by TinyTuya**. Интерфейсы Agent и SNMP не нужны. Запомни **техническое имя хоста**.
4. В элементах `tuya.poll.ok` и `tuya.status.raw` (тип **Zabbix trapper**) заполни поле **Allowed hosts / Разрешённые узлы** адресом источника, который видит Zabbix Server. При Docker NAT это часто адрес шлюза bridge-сети, а не `127.0.0.1`. Можно использовать макрос. Порт 10051 должен быть доступен только в доверенной сети.
5. Запусти интерактивную конфигурацию — она запросит реальные параметры и сохранит локальный `.env` с правами 0600:

```sh
cd /Volume1/docker/tinytuya-zabbix
./scripts/setup.sh
docker compose build
docker compose run --rm tinytuya-zabbix --dry-run
docker compose run --rm tinytuya-zabbix --once
docker compose up -d
docker compose logs --tail=30 -f tinytuya-zabbix
```

`--dry-run` только читает розетку, `--once` один раз отправляет показания, `up -d` запускает постоянный опрос. При публикации порта Zabbix 10051 на самом TNAS и `network_mode: host` адрес `127.0.0.1` подходит.

Остановка:

```sh
docker compose down
```

## Готовый образ из Docker Hub

После публикации образа в своём Docker Hub добавь `DOCKERHUB_USERNAME` в локальный `.env`, затем:

```sh
docker compose -f compose.hub.yaml pull
docker compose -f compose.hub.yaml up -d
```

Python и все зависимости будут только внутри контейнера, в TOS ничего дополнительно не устанавливается.

## Что попадёт в Zabbix

| Метрика | Ключ | Источник |
|---|---|---|
| Успешность опроса | `tuya.poll.ok` | 1 — работает, 0 — локальный опрос завершился ошибкой |
| Исходный JSON | `tuya.status.raw` | Нормализованные данные и DPS |
| Состояние реле | `tuya.relay` | DPS 1, 1 или 0 |
| Напряжение | `tuya.voltage` | DPS 20 / 10, В |
| Ток | `tuya.current` | DPS 18 / 1000, А |
| Мощность | `tuya.power` | DPS 19 / 10, Вт |
| Таймер | `tuya.countdown` | DPS 9, если поддерживается |
| Режим восстановления | `tuya.restore.mode` | DPS 38, если поддерживается |

DPS и коэффициенты масштабирования настраиваются. Значения по умолчанию соответствуют одной проверенной Tuya-розетке, но не всем моделям. Перед настройкой тревог по электрическим показателям сверь коэффициенты с данными своего устройства.

Есть триггеры трёх последовательных ошибок опроса, отсутствия данных более пяти минут, повышенной мощности и напряжения за границами диапазона. Пороги регулируются макросами `{$TUYA.POWER.MAX}`, `{$TUYA.VOLT.MIN}`, `{$TUYA.VOLT.MAX}`.

## Безопасность

- **Никогда не отправляй в Git** `devices.json`, `.env`, снимки TinyTuya, Tuya API Secret и Local Key. Эти файлы исключены через `.gitignore` и `.dockerignore`.
- Файл ключей монтируется в контейнер **только для чтения** и не попадает в Docker-образ.
- Файловая система контейнера только для чтения, capabilities отключены, привилегии не повышаются.
- Используется сеть хоста для LAN-подключения; не открывай TCP 6668 и Zabbix TCP 10051 в интернет.
- Протокол передачи данных Zabbix sender в этом проекте **не шифруется**. Используй доверенную LAN или защищённый туннель.
- **Allowed hosts** в обоих trapper-элементах должен ограничивать адреса отправителей. При Docker NAT обычно требуется адрес шлюза сети контейнера Zabbix.

## Решение проблем

| Ошибка | Что проверить |
|---|---|
| `Device ID was not found` | Device ID и монтирование `devices.json` |
| `No valid DPS map` | Local Key, IP, версию локального протокола |
| `processed: 0; failed: 2` | Техническое имя хоста, два элемента trapper, их Allowed hosts, кеш конфигурации сервера |
| `Connection refused` | Доступность Zabbix Server на TCP 10051 |
| `tuya.poll.ok = 0` | Ошибка локального опроса Tuya |
| Опрос перестал обновляться | Логи Docker и триггер `nodata()` |

После изменения Allowed hosts можно обновить кеш конфигурации Zabbix Server командой `zabbix_server -R config_cache_reload` внутри контейнера сервера.

## Тестирование и публикация

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q src
```

При загрузке в GitHub автоматически запускаются тесты и сборка образа. Пошаговая инструкция по GitHub и Docker Hub: [docs/PUBLISHING.ru.md](docs/PUBLISHING.ru.md).

**UUID шаблона сохранены** от предыдущей версии, чтобы можно было обновлять существующий шаблон. Импорт в конкретный Zabbix всегда лучше сначала проверить.
